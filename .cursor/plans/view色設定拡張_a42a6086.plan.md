# view色設定拡張 実装計画

## 目的

view一覧の各viewに色を設定できるようにし、`views[].bg-color` への永続化、RGB手入力、履歴選択、色解除を提供する。  
加えて active view の色反映は以下に限定して実現する。

- view一覧: 名前表示領域以外
- Task List View(Custom) / Table View(Custom): 指定領域

※ active view の名前表示領域は従来通りアクセント色を維持する。  
※ 組み込みのTable View等は対象外（コード変更不可のため）。

## 合意事項（2026-03-03反映）

- Custom view（Task List View(Custom)/Table View(Custom)）の着色は、view一覧機能とは分離して各Custom viewコード側で `bg-color` を読み取って反映する。
- `enableBasesViewListSidebar = false` でも、上記2つのCustom view着色は有効にする。
- RGB履歴はグローバル5件（baseファイル単位ではない）。
- 不正値はすべて未設定扱いにし、機能実装前と同等の表示へフォールバックする。

## 仕様確定

### 1. `views[].bg-color` 保存形式

- プリセット: 文字列ID（英小文字）
  - 確定（8色）: `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple`, `pink`
- RGB指定: `rgb(r,g,b)` 形式
  - 例: `rgb(120,200,255)`
  - 入力受理: `rgb(...)` の大文字小文字は区別しない（`RGB(...)`も受理）、要素前後の空白は許容
  - 数値は10進整数のみ受理（符号/小数/指数表記は不許可）
  - 範囲は各要素 `0..255` のみ受理
  - 保存時は `rgb(0-255,0-255,0-255)` の正規化済み小文字文字列（空白なし）で統一
- 不正値（未知プリセット、範囲外RGB、構文不正、空文字など）は読み取り時に `null` として扱う
- 備考: 1つのbase内で同名viewは存在しない前提のため、view特定はname一致のみで問題ない

### 2. 色適用ルール

- view一覧（`BasesViewListSidebarService`）
  - 各view行の「名前表示領域」は、そのviewの色で着色（非active時）
  - active viewの「名前表示領域」には `bg-color` 着色を適用せず、常にアクセント色を維持
  - active viewに有効な`bg-color`がある場合のみ、view一覧の「名前表示領域以外」を同系色で着色
- Task List View(Custom) / Table View(Custom)
  - active view type が `tasknotesTaskListCustom` / `tasknotesCustomTable` のときだけ反映
  - 各ビュー実装内で `.base` の active view `bg-color` を直接取得して適用
  - 表示色はさらに淡色化した色を使い、可読性を維持
  - Task List: ノート（タスクカード）表示領域以外を着色
  - Table: プロパティ名ヘッダー領域・Grouping見出し領域を着色

### 3. RGB履歴仕様

- 保存先: `BaseViewsSettings`（`data.json`）
- 件数: 最大5件（グローバル）
- 履歴対象: `rgb(r,g,b)` のみ
- 正規化ルール: 受理時点で `rgb(r,g,b)`（小文字・空白なし）に正規化
- 追加時: 正規化後文字列で重複判定し、先頭追加、重複除去、最大5件へ切り詰め
- 不正履歴値はmigration/読込時に除去

## 機能別ステップ

1. **保存形式とデータ層の追加**

- `BaseViewListYamlStore` に `bg-color` 取得/更新APIを追加する。
- `description` と同様の対象view一致ロジックで `bg-color` を設定/削除する。
- 取得時は `normalizeBgColorValue()` を通し、不正値は `null` を返す。

1. **色モデル/共通ロジックの実装**

- プリセットID -> CSS変数 -> 実RGB解決関数を実装する。
- `rgb(r,g,b)` のパース/正規化関数を実装する（空白/大文字許容入力を正規化）。
- テーマ判定（light/dark）に応じた淡色化、文字色（黒/白）自動判定を実装する。
- すべての不正入力を「未設定」として扱う判定ロジックを共通化する。

1. **設定（RGB履歴）**

- `BaseViewsSettings` にRGB履歴配列（グローバル5件）を追加する。
- `DEFAULT_SETTINGS` に初期値を追加する。
- migrationで旧データ/不正値を正規化し、後方互換を維持する。

1. **view行コンテキストメニュー拡張**

- view行メニューに `Color` セクションを追加する。
- プリセット8色、`RGBで指定`、履歴5件、`色を消去` を実装する。
- 操作時は `.base` 更新 -> 再描画、RGB確定時は履歴を更新して `saveSettings()` する。

1. **RGB入力モーダル**

- `R/G/B` 各入力（0-255）とライブプレビューを持つモーダルを追加する。
- `OK` で `rgb(r,g,b)` を返し、`キャンセル`/閉じるで無変更とする。

1. **表示反映（view一覧）**

- 各viewの名前表示領域を着色する（非active view）。
- active viewの名前表示領域は `bg-color` を適用せず、アクセント色のまま維持する。
- active viewに有効色がある場合のみ、view一覧の名前表示領域以外を着色する。

1. **表示反映（Task List View(Custom) / Table View(Custom)）**

- `TaskListViewCustom` / `CustomTableView` 側で active view の `bg-color` を直接取得して反映する。
- この処理は `enableBasesViewListSidebar` のON/OFFに依存させない。
- view切り替え時は必ず `bg-color` を再取得し、再描画へ反映する。
- 無効値・未設定時は着色しない（既存表示維持）。
- Task List: ノート（タスクカード）表示領域以外を着色する。
- Table: プロパティ名ヘッダー領域・Grouping見出し領域を着色する。

1. **テスト拡充**

  - `bg-color` 保存/削除/取得
  - 不正値を未設定扱いにする挙動
