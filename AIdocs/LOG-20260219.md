## 2026-02-19: Task List view custom の unnest反映と2段階グループ即時更新の修正

### 実施内容
- `TaskListViewCustom` と `CustomTableView` の差分を比較し、以下を確認。
  - `CustomTableView` は `render()` 毎に `readViewOptions()` を再評価し、`onDataUpdated()` で設定差分時は即時描画。
  - `TaskListViewCustom` は option を初回のみ読み取り、設定変更後も古い `subGroup/unnest` を保持していた。
- `src/bases/TaskListViewCustom.ts` を修正。
  - `render()` 毎に `readViewOptions()` を実行するよう変更。
  - `onDataUpdated()` を override し、設定シグネチャ差分時は即時描画、通常更新のみ300msデバウンスへ変更。
  - `unnestMultiValueGroup` の読み取りを bool正規化し、文字列値（`"true"` / `"false"`）も意図通り解釈するよう修正。
  - `subGroup` は trim後、空文字を `null` 扱いに統一。
  - 1段階目グルーピングでも `unnestMultiValueGroup=true` かつ primary groupBy が multi-value のとき、Bases既定groupを再構築してunnest展開するよう修正。
- 回帰防止テストを `tests/unit/bases/taskListCustomGrouping.test.ts` に追加。
  - `readViewOptions()` の bool正規化テスト。
  - `onDataUpdated()` の「設定変更は即時、通常更新はデバウンス」テスト。
  - 1段階目グルーピングの unnest ON/OFF 挙動テスト。

### 判断理由
- ユーザー報告の2症状（unnest不発・2段階グループ反映遅延）は、どちらも「設定変更が描画に同期されない」同一根本原因で説明できるため、個別パッチではなく描画同期モデルを CustomTable寄せへ揃えた。

### 影響範囲
- 対象は `tasknotesTaskListCustom` のみで、既存 `tasknotesTaskList` と `tasknotesCustomTable` の挙動には影響しない。

### 補足
- `node` / `npm` が実行不可の環境のため、テスト実行は未実施（テストコード追加のみ）。
