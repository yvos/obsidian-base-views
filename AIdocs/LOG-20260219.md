## 2026-02-19: Custom Table のグルーピング表示不整合と解除失敗の修正

### 実施内容
- `src/bases/CustomTableView.ts` を修正。
  - grouped描画の仮想化閾値を `0` に変更し、1段階/2段階を含む grouped 時の描画を常に virtual 経路へ統一。
  - 非グループ描画時の `entries` 抽出を `groupedData[0]?.entries` 依存から `allEntries` 優先へ変更し、先頭groupが空配列のときに誤って0件扱いになる経路を解消。
  - `groupBy` 解決ロジックを追加し、`config`（`getAsPropertyId("groupBy")` / `get("groupBy")`）を優先して参照。
  - `config` で groupBy 未設定と判定できる場合は `controller.query.views` へフォールバックしないよう変更し、解除直後に stale な groupBy を拾って再グループ化する経路を抑止。

### 判断理由
- 1段階時の見た目揺れは「データ条件」ではなく「normal/virtual描画ルート差」に起因するため、grouped経路を1つに統一するのが最短で一貫性を担保できるため。
- 解除失敗は groupBy 判定の情報源が古い状態を参照することが主因だったため、最新状態を持つ `config` を優先し、未設定時の無条件フォールバックを避ける設計へ変更した。
- `No rows match the current filters.` は空配列truthyの分岐ミスで再現するため、エントリ抽出を `allEntries` 基準に寄せて誤判定を防止した。

### 影響範囲
- `tasknotesCustomTable` の grouped 表示が常に virtual レイアウト（ヘッダ1回表示）になる。
